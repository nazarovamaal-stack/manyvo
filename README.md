# Manyvo

Веб-приложение для сравнения 2–5 вариантов. Участник отправляет личный выбор и прогноз большинства. Заказчик получает два распределения и сверяет прогноз с бизнес-фактом.

Реализация следует пяти согласованным PDF в [docs](docs). До закрытия исследования распределения скрыты и от участников, и от заказчика.

## Запуск

Нужен Python 3.9 или новее. Внешние Python-пакеты, Node.js и сборка интерфейса для запуска не требуются.

```sh
python3 -m manyvo.server --seed-demo
```

Открыть <http://127.0.0.1:8000>. При первом запуске на пустой базе `--seed-demo` создаёт примеры и аккаунты. Существующие данные не перезаписываются. Для отображения кнопок демоаккаунтов оставляйте этот флаг при следующих запусках.

Демоаккаунты: `owner@manyvo.local` — заказчик, `anna@manyvo.local`, `ivan@manyvo.local`, `alina@manyvo.local`, `max@manyvo.local`, `lena@manyvo.local` — участники. Пароль всех демоаккаунтов: `manyvo-demo`.

Без примеров аккаунты создаются локально:

```sh
python3 -m manyvo.server --create-user
```

## OpenAI

В локальном `.env` заполнить `OPENAI_API_KEY` и перезапустить сервер. Если файла ещё нет, создать его по `.env.example`. Ключ не передаётся браузеру и исключён из Git.

Используется [Moderation API](https://developers.openai.com/api/docs/guides/moderation) с `omni-moderation-latest`. Каждый вариант заново проверяется вместе с названием и вопросом, включая загруженное изображение. Запрет, отсутствие ключа, таймаут или ошибка сервиса возвращают исследование в черновик. При отправке на модерацию материалы передаются OpenAI.

Для демонстрации без внешних запросов:

```sh
python3 -m manyvo.server --demo --seed-demo
```

В этом режиме проверка разрешает материалы без обращения к OpenAI, а интерфейс показывает «Деморежим». Это отдельный режим запуска, он не включается автоматически при ошибке API. Примеры исследований создаются как синтетические демоданные и не подтверждают показатели пилота.

## Что работает

- Черновики, 2–5 текстовых вариантов или изображений PNG/JPEG до 5 МБ, аудитория и квота 2–500.
- Версии черновика, модерация перед публикацией, запрет редактирования открытого исследования.
- Аккаунты заказчика и участников, серверные сессии, проверка возраста и страны.
- Одна неизменяемая пара ответов на аккаунт. Повторные запросы не дублируют ответы и баллы.
- Закрытие по квоте или через 24 часа, два распределения, ничьи, недобор и ноль ответов.
- Базовый балл и бонус за прогноз лидера личных предпочтений, история начислений.
- Версии бизнес-факта, сверка лидеров прогнозов и факта, метрики по событиям.

## Проверки

```sh
python3 -m unittest discover -s tests -v
node --test tests/ui.test.cjs
node --check static/app.js
```

Python-тесты проверяют бизнес-правила, конкуренцию за последнее место, идемпотентность, откат транзакций при сбое, модерацию на подставных ответах и полный HTTP-сценарий. Тесты интерфейса выполняют рендеринг в изолированном JavaScript-контексте, без настоящего браузера. Они не заменяют визуальную проверку.

Нагрузочный профиль TC-13 — 100 авторизованных пользователей, 10 минут. Каждая волна открывает новое исследование и отправляет по одной новой паре от каждого участника. База и сервер временные, OpenAI не вызывается:

```sh
python3 scripts/load_test.py --seconds 600 --users 100 --output reports/load-test.json
```

TC-18 требует реального пилота с людьми. Он не выполнен. Достижение 50 ответов за час и завершения ≥80% не подтверждено демоданными или автоматическими тестами.

## Хранение и устройство

- `manyvo/core.py` — бизнес-правила и транзакции SQLite.
- `manyvo/server.py` — сервер, авторизация, JSON API, фоновое закрытие раз в секунду.
- `manyvo/moderation.py` — OpenAI и отдельная заглушка для деморежима.
- `manyvo/schema.sql` — схема SQLite. Данные по умолчанию находятся в `data/manyvo.sqlite3`.
- `static/` — интерфейс на HTML, CSS и JavaScript.
- `tests/` — автоматические проверки, `scripts/` — нагрузочный сценарий.

Ответ и базовый балл сохраняются одной транзакцией. Закрытие и бонусы также атомарны. Уникальные ограничения защищают от повторных ответов и начислений. Первый вход участника в исследование записывается один раз. Журнал содержит обезличенный ID участника, тип, время события, ID исследования и версию факта при его изменении.

API: `POST /api/login`, `GET /api/me`, `POST /api/logout`, `GET/POST /api/studies`, `GET/PUT /api/studies/{id}`, `POST /api/studies/{id}/publish`, `/answer`, `/fact`, `GET /api/history`, `GET /api/metrics`. Изменяющие запросы требуют JSON, `X-Manyvo-Client: web` и CSRF-токен сессии, кроме входа. Пароли хешируются PBKDF2, cookie имеет HttpOnly и SameSite=Lax.

## HTTPS

Обычный HTTP разрешён только на loopback для локальной разработки. Для доступа с других устройств нужен TLS:

```sh
python3 -m manyvo.server --host 0.0.0.0 --cert /path/to/cert.pem --key /path/to/key.pem
```

В `.env` задать `MANYVO_ALLOWED_HOSTS=your-domain.example`. При TLS cookie получает Secure. Локальный HTTP-режим — исключение разработки, он не подтверждает HTTPS-часть NFR-03. Сертификат и приватный ключ в Git не сохраняются.

Регистрация, подтверждение возраста, оплата, расширение браузера и расходование баллов находятся за пределами выбранной фичи. Профили демоаккаунтов заданы заранее.
