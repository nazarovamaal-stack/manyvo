# Manyvo

Полный MVP по one-pager: заказчик запускает микроисследование, участник отвечает через браузерное расширение, получает баллы и обменивает их на награды. После запуска заказчик сверяет прогноз с бизнес-фактом.

Стек: **Next.js + TypeScript, расширение TypeScript / Manifest V3, Go, PostgreSQL, Redis**. Прежняя реализация Python/SQLite сохранена в Git-теге `mvp-core-python`.

## Запуск

Нужны Docker Compose и Node.js 22+. В `.env` указать `OPENAI_API_KEY`. Пример настроек — `.env.example`, ключ в Git не попадает.

```sh
docker compose up --build -d
npm ci
npm run package -w @manyvo/extension
```

Сайт: <http://localhost :3000>. API доступен локально на порту 8088, PostgreSQL на 54329, Redis на 63799. Все внешние порты Compose привязаны к loopback.

Для отдельной демонстрации без обращения к OpenAI:

```sh
DEMO_MODE=true docker compose up --build -d
```

`DEMO_MODE=true` разрешает материалы без ИИ-проверки и явно отмечается в интерфейсе. Он никогда не включается автоматически при сбое API. Чтобы вернуться к реальной модерации:

```sh
DEMO_MODE=false docker compose up -d --force-recreate api
```

По умолчанию `SEED_DEMO=true` создаёт примеры в пустой базе. Демовход: `owner@manyvo.local` — заказчик, `anna@manyvo.local`, `ivan@manyvo.local`, `alina@manyvo.local`, `max@manyvo.local`, `lena@manyvo.local` — участники. Пароль: `manyvo-demo`. На сайте также доступна регистрация заказчиков и участников с возрастом и страной.

## Установка в Яндекс Браузер

1. Собрать расширение командой `npm run package -w @manyvo/extension`.
2. Открыть `browser://tune` в Яндекс Браузере.
3. Перетащить `artifacts/manyvo-yandex.crx` в окно браузера и подтвердить установку. Это формат и способ, описанные в [справке Яндекса](https://yandex.ru/support/browser/ru/personalization/extension#kak-dobavit-novoe-rasshirenie-v-brauzer).
4. На сайте войти участником → **Расширение** → **Создать код подключения**.
5. В настройках расширения указать `http://localhost:3000` и вставить код. Код выдаёт доступ к аккаунту, его нельзя публиковать.
6. Нажать **Проверить уведомление**. При необходимости разрешить уведомления Яндекс Браузеру в настройках операционной системы.

Готовые файлы: `artifacts/manyvo-yandex.crx`, ZIP с содержимым расширения и распакованная папка `extension/dist`. Ключ подписи CRX находится в игнорируемой `data/extension-keys`, а не внутри пакета.

Расширение проверяет события через `chrome.alarms` примерно раз в минуту. При закрытом браузере или спящем компьютере мгновенной доставки нет. После возвращения в сеть неполученные события проверяются повторно. Это поведение [фоновых будильников браузера](https://developer.chrome.com/docs/extensions/reference/api/alarms).

## Что реализовано

| Возможность one-pager | Где находится |
| --- | --- |
| 2–5 вариантов, тексты и изображения, аудитория, квота | Веб-интерфейс заказчика, Go API |
| Личный выбор и прогноз большинства | В расширении и на сайте, одна атомарная пара на аккаунт |
| ИИ-модерация текста и изображений | OpenAI Moderation API, Go-обработчики заданий, очередь Redis |
| Уведомления о новых и завершённых исследованиях | Постоянные записи PostgreSQL, фоновый обработчик расширения, системные уведомления |
| Базовый балл и бонус за прогноз | Серверный журнал операций и баланс в обоих интерфейсах |
| Колесо призов и гарантированные награды | В расширении и на сайте, серверная выдача уникальных купонов |
| Закрытые результаты, ничьи и недобор | Два распределения после квоты или 24 часов |
| Ввод факта и сверка | Отчёт владельца, версии бизнес-факта |

Заказчик до закрытия видит число принятых ответов. Участник — только свою пару. Бонус определяется лидерами **личных выборов**, а сверка с фактом использует лидеров **прогнозов**.

## Награды

Подтверждённая демоэкономика: прокрутка стоит **1 балл**, четыре равновероятных сектора дают **25% шанса на купон**. Демогарантированная награда стоит **10 баллов**. Демокупоны обозначены явно и не имеют денежной стоимости.

В разделе заказчика **Награды участникам** можно добавить настоящие купоны, описание и условия, пополнить запас кодов или приостановить награду. Для колеса активен один вид приза. Перед его заменой нужно приостановить предыдущий. Деньги и физическая доставка не интегрированы: MVP выдаёт цифровые коды, которые загрузил заказчик.

Выигрыш определяет сервер криптографическим генератором. Повтор запроса с тем же идентификатором возвращает прежний результат. Списание и выдача кода происходят в одной транзакции PostgreSQL. Баланс не уходит в минус, один код не выдаётся двум людям. Если призовой запас колеса закончился, прокрутка отключается до пополнения, а вероятность не меняется молча.

## Уведомления и подключение

Новое исследование создаёт уведомления подходящей по возрасту и стране аудитории. Завершение — тем, чьи ответы приняты. Начисления и получение награды также создают события для участника.

Подключение расширения выполняется отдельным отзываемым кодом на 30 дней. Ключ OpenAI в расширение не передаётся. Доступ хранится в `chrome.storage.local`, не синхронизируется с аккаунтом браузера. Веб-сессия и подключение расширения независимы. Отключить устройство можно на сайте.

Полученные браузером уведомления подтверждаются отдельно от отметки «Прочитано». Расширение сохраняет идентификаторы показанных уведомлений, чтобы сетевой повтор не создавал повторное оповещение. При запрете уведомлений они остаются неподтверждёнными до следующей проверки.

## Проверить новый опрос и завершение

1. Подключить расширение к аккаунту Анны, оставить Яндекс Браузер запущенным.
2. На сайте войти заказчиком и создать исследование с двумя вариантами, квотой 2, страной Россия и возрастом 18–65.
3. После успешной модерации дождаться уведомления Анне. Открыть опрос из уведомления и отправить оба ответа в расширении.
4. На сайте войти Иваном и ответить на тот же опрос. Два принятых ответа закроют исследование.
5. Расширение Анны сообщит о завершении и начислениях. В нём можно открыть личный итог, колесо и гарантированные награды.
6. На сайте заказчика проверить два распределения, добавить значения бизнес-метрики и выполнить сверку.

Тестовые сообщения из кнопки «Проверить уведомление» проверяют канал доставки. Публикация и закрытие выше проверяют реальные продуктовые события.

## Очередь модерации

Публикация фиксирует версию исследования и задание в PostgreSQL. Диспетчер отправляет ID задания в Redis, обработчики проверяют каждый вариант через [OpenAI Moderation API](https://developers.openai.com/api/docs/guides/moderation). Тексты и изображения отправляются только с сервера.

Задание имеет срок обработки и номер попытки. Повторная доставка не публикует исследование повторно, устаревший результат не разрешает новую версию. После остановки обработчика задача с истёкшей арендой возвращается в очередь. PostgreSQL хранит незавершённые задания, поэтому временный сбой Redis не теряет запрос публикации. Запрет и ошибка OpenAI возвращают редактируемый черновик с причиной.

## Проверки

```sh
npm ci
npm run typecheck
npm run build
npm run test:extension
npm run test:web
```

Интеграционные тесты Go используют настоящие PostgreSQL и Redis. Для каждого теста создаётся отдельная случайная схема, после проверки удаляется только она. Для очереди тестов используется отдельная Redis DB 15.

```sh
TEST_DATABASE_URL='postgres://manyvo:manyvo-local-only@127.0.0.1:54329/manyvo?sslmode=disable' \
TEST_REDIS_URL='redis://127.0.0.1:63799/15' \
go -C backend test ./... -race -count=1
```

Без `TEST_DATABASE_URL` интеграционные проверки пропускаются. Нагрузочный профиль запускается отдельно:

```sh
TEST_DATABASE_URL='postgres://manyvo:manyvo-local-only@127.0.0.1:54329/manyvo?sslmode=disable' \
TEST_REDIS_URL='redis://127.0.0.1:63799/15' \
RUN_LOAD_TEST=true LOAD_SECONDS=600 LOAD_REPORT='../../../reports/load-test.json' \
go -C backend test ./internal/platform -run '^TestLoadProfile$' -count=1 -timeout 15m -v
```

Сохранённый [нагрузочный отчёт](reports/load-test.json): 600 секунд, 100 пользователей в каждой волне, 270 400 запросов без ошибок. p95 чтения — 0,073 с, отправки пары — 0,322 с. Результат относится к Go API с PostgreSQL и указанному синтетическому профилю, без Next.js, изображений и внешней ИИ-модерации. Отдельная [сквозная проверка](reports/smoke.json) проходит через работающий Next.js и Go API.

Реальный пилот с людьми, цель 50 ответов за час и завершение ≥80% отдельно не подтверждены. Системный показ уведомления в установленном Яндекс Браузере и запрос к OpenAI с личным ключом требуют проверки в пользовательском окружении.

## Структура

- `apps/web` — Next.js и React-интерфейс на TypeScript.
- `backend` — Go API, бизнес-правила, очередь и SQL-схема.
- `extension` — TypeScript, Manifest V3, сборка CRX3 и тесты обработчика уведомлений.
- `compose.yaml` — четыре сервиса с постоянными томами PostgreSQL и Redis.
- `docs` — one-pager и четыре согласованных документа по основной фиче.
- `scripts/migrate_sqlite.py` — разовый перенос прежней локальной базы в пустой PostgreSQL. Исходный файл сохраняется, старые сессии требуют нового входа.

HTTP в конфигурации Compose предназначен для локальной разработки. Для внешнего размещения нужен HTTPS перед Next.js и корректный `APP_ORIGIN` у API. Ключи, пароли подключения, данные PostgreSQL, исходная SQLite-база и ключ подписи расширения в Git не сохраняются.

Код и проверки подготовлены с помощью Codex.
